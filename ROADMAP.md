# Covenant Standard (CVN) Roadmap

Last reviewed against the code: 19 November 2026 (release candidate 11).

A box is ticked only when the feature is built **and** has been seen working on a live network. Today that means the development network (`devnet`), run across a miner, six seed servers on three continents and testers' machines; the CVN Testnet has not started. Everything else says what exists and what is missing.

## Phase 1: A working chain (test network)

The block heights in this phase are those of the first test network (`testnet-1`), where these features were first built and run. That network has been retired; the development network and the CVN Testnet run all of them from the first block.

- [x] **45-second blocks with per-block difficulty adjustment.** Live since block 2,500.
- [x] **Uncle rewards: tried, then dropped.** On the first test network, when two miners solved the same height the next block paid the loser 20% of the reward. Nodes could not verify that share, so it was removed: a block pays its own miner only.
- [x] **Sending CVN between wallets.** Live since block 6,100. Every transfer is signed by its owner; nodes reject transfers that spend coins that do not exist, belong to someone else, or pay out more than they take in.
- [x] **Block contents locked by proof of work.** The block hash covers every transaction in full.
- [x] **Whole-number amounts.** Live since block 6,600. Every amount is checked as a whole number of units (1 CVN = 100,000,000 units) with no rounding tolerance.
- [x] **Fork recovery and sync from scratch.**
- [ ] **Chain selection by total work.**
  - *Have:* built and running on every node. A node keeps its chain unless a competing branch proves more mining work, and restores its own blocks if the competing branch fails validation.
  - *Also have:* seen in part. On the development network two blocks have competed at one height and every seed chose the same winner. And in the tests that run several real nodes on one machine, a miner that had mined three blocks cut off from the others gave them up for the network's chain when it returned, and its coins were gone on every node.
  - *Missing:* a branch of several blocks being replaced on a live network, across machines.
- [x] **Desktop wallet (Windows) and text wallet (Linux and Windows).**
- [ ] **Recovery words and a saved key.** A private key is also shown as 24 ordinary English words, which are the same key written another way with a check built in (the word list is the one Bitcoin wallets use); either form opens the wallet. The text wallet can keep the key on the computer locked with a password, which either wallet then accepts where it asks for the key. In the text wallet a key is not shown as it is typed, on Windows as on Linux.
  - *Missing:* built and tested, but nobody other than the developer has yet reported using either.

## Phase 2: Network

- [x] **Block and transfer gossip** between all nodes.
- [x] **Mining without port forwarding.** Nodes behind a home router receive blocks through an outbound connection; routers that support it are configured automatically.
- [x] **Peers remembered between restarts**, and six seed nodes on three continents, none of which mines.
- [x] **Miner waits when its node is behind**, so it never mines on a stale chain.
- [ ] **Capacity for a large network.**
  - *Have:* comfortable for roughly 100–150 nodes.
  - *Also have:* a block that arrives while a node is catching up is fetched as soon as the catch-up ends. It used to be dropped and not asked for again for up to thirty seconds, which left the node a block behind for a whole interval.
  - *Missing:* persistent connections and announce-then-fetch block relay, needed before a large public launch. Blocks and transfers from one address also share a single message allowance, so a node that passes on a burst of transfers can have its next block ignored by the receiver.
- [x] **Block size limit enforced.** A block may not exceed 300,000 bytes, and every node enforces it. Seen at the limit on the development network: five blocks of about 296,700 bytes (76 transfers of 50 outputs each) and six of about 286,500 bytes (16 transfers of 200 inputs each) reached all six seeds within 5 seconds of being mined, against an interval of 45. An empty block took up to 2.7 seconds over the same routes. The tool that fills blocks is in the source and is left out of every release.
- [ ] **A new node joins the network that is there.**
  - *Have:* a mining node that was given seeds asks them for their first block before anything else. If one has the same first block it carries on. If none answers and it has no blocks, it says so, mines nothing, and carries on by itself once one answers. If they answer and are on another chain, it stops and says what to check. A seed address that cannot be read stops the program and is named. Before this, a newcomer whose seeds could not be reached began a chain of her own without a word, which is how the fault was found.
  - *Missing:* the ordinary case runs on every machine of the development network; the waiting and the refusal have been seen only in the tests with several real nodes on one machine.
- [x] **Backups of the chain.** A node saves a copy of its chain two minutes after it starts and then once a day, checks the copy (every block present and linked, each block matching its identifier, the first block this network's, and coins plus vault equal to what was issued), and keeps the newest seven. A backup can be checked by hand and restored. Seen on the development network: a backup at block 2,066 passed its check with 103,300 CVN held, exactly 2,066 times 50. Restoring has only been run in tests.
- [ ] **How often a block loses the race.**
  - *Have:* every node counts the heights at which it saw two valid blocks compete, logs each one, and reports the share with its newest block. Running on the miner and all six seeds.
  - *Missing:* a meaningful figure. It needs several miners of similar size for days; with one large miner the count so far is none. Under about 3 in 100 is ordinary for 45-second blocks. More than that for long is a reason to make blocks travel faster first, and only well above 5 in 100 after that would paying the loser a share be worth building.
- [ ] **Automatic router port mapping (UPnP).**
  - *Have:* the node finds the router, maps its ports, renews the mapping and detects carrier-grade NAT.
  - *Missing:* only one machine per router can hold the ports; a second falls back to relay mode (it still mines, but nobody can sync from it). No NAT-PMP/PCP fallback for routers without UPnP.
- [ ] **Peer discovery without the seeds.**
  - *Have:* nodes exchange peer lists and reuse remembered peers on restart.
  - *Missing:* not yet proven with the seeds actually down; a brand-new node still depends on the built-in seed addresses.
- [ ] **Wire protocol.**
  - *Have:* length-prefixed frames with a size limit and a message key.
  - *Missing:* payloads are uncompressed text, and the key is shared by every node, so it filters noise but does not authenticate peers.
- [ ] **Peer banning and scoring.**
  - *Have:* per-address rate limiting, a 5-minute ban after repeated malformed messages, and a 10-minute ban for sending a block whose proof of work is false.
  - *Missing:* no ban for sending other invalid blocks or invalid transfers, no preference for reliable peers when connections are full, and bans are lost on restart.
- [x] **Mempool safeguards.** A transfer is checked for a valid signature and real coins before it is stored or passed on; the mempool has a size limit and a 2-hour expiry.

## Phase 3: Launch rules (in development)

These are built and are the only rules in the program. They run on the development network (`--network devnet`), which has its own key, ports and files, and will run on the CVN Testnet when it starts. Most boxes below stay unticked until that public test has happened.

- [x] **Separate network identities** and one place for every chain setting.
- [x] **Amounts stored as whole units.** Every amount is a whole number of units, inside the program, in blocks, in the coin database and in what is hashed and signed. No decimal number appears anywhere in the rules. Seen across the development network: after thousands of blocks and transfers, every machine held the same balances and they added up to exactly what had been issued.
- [ ] **Supply schedule:** 50 CVN per block, halving every 7 years for 49 years; 486,727,500 CVN in total.
  - *Have:* built and enforced, including what happens after the last reward: a block may then pay its miner only the fees of the transfers it contains.
  - *Missing:* a public testnet of the launch rules.
- [ ] **Exact 45-second average.**
  - *Have:* built. The difficulty rule applies from block 1 and also steers by how far the chain is from its schedule. In a simulation of 300,000 blocks it averages 45.00 seconds, including through large swings in mining power; without the schedule term it averages about 44.7.
  - *Also have:* on the development network, under the present form of the rule, blocks 1 to 3,379 averaged 45.11 seconds, with a 31-minute stop of the only large miner inside that span.
  - *Missing:* a public testnet, and from its first day a starting difficulty for the real launch. The CVN Testnet itself starts at 2,500,000.
- [ ] **A difficulty rule a large miner cannot game.**
  - *Have:* three changes made after review and simulation. Relief for a late block (difficulty halved after six minutes without a block) stays with that block and is not passed to the next, so a miner who stops and starts no longer collects a run of cheap blocks. Each block's step is applied as e^x, in whole-number arithmetic that is identical on every machine, so a run of steps depends only on how much time the blocks' dates span and choosing dates gains nothing. And every miner reaches the six-minute halving at the same moment, so nobody has a head start. Before these, a miner with nearly all the mining power could take a third more coins by mining in bursts, or 13% more by choosing dates; in simulation against the real arithmetic both now gain nothing, and the chain holds 45 seconds. The findings and the simulations are in `audit/FINDINGS_ROUND_4.md` and `audit/FINDINGS_ROUND_5.md`.
  - *Also have:* running on the development network. When its one large miner stopped for 31 minutes, the block that ended the gap was mined at the minimum difficulty and the very next one at 618,646, a little over half of the 1,115,869 before the gap: the relief was not passed on.
  - *Missing:* a public testnet. A miner of any size who mines only when difficulty dips still earns 10% to 30% more per hash while earning fewer coins in total; that was left alone, because the rule that removes it stalls for an hour or more when miners really leave.
- [ ] **The vault and the fee split.**
  - *Have:* built. The vault is a counter kept by the rules; no key can spend from it. While new coins are still being issued, a fifth of every block's fees goes into it and the miner keeps the rest. Every block, the vault pays a fixed fraction of what it holds to that block's miner.
  - *Also have:* the fee split seen on the development network. After 479 transfers paying 0.001 CVN each, every node's vault held 0.0958 CVN, which is a fifth of those fees, and all seven machines agreed.
  - *Missing:* a public testnet of the launch rules. The vault's payout has not been seen live: on a real schedule the amount per block is too small to be a coin until the vault holds far more.
- [ ] **Minimum output size.** Built: a transfer output must be at least 0.0001 CVN, and wallets leave smaller change to the miner.
- [ ] **Recycling of long-unmoved coins** into the vault.
  - *Have:* built. Every coin has an age. A coin not spent for 7 years has a fifth of its value moved into the vault at the end of the block that reaches that age, and then starts a new 7-year count; a coin so small that it would be left below the minimum output is not touched at all. Spending a coin, even to yourself, resets its age, so an owner who still holds the key loses nothing. The sweep is reversed if its block is removed in a reorganisation. Anything a block could have paid its miner but did not also goes to the vault, so nothing issued is ever destroyed.
  - *Missing:* a public testnet.
- [x] **Combine my coins (wallet).** In the text wallet and the desktop wallet. It sends a wallet's coins back to its own address in groups of up to 200, smallest first, each group becoming one coin; up to 5,000 coins per use. Each group is an ordinary transfer, so it needs no network rule. It removes the 200-coins-per-transfer limit as a practical obstacle.
- [x] **Renew my coins (wallet).** In the text wallet and the desktop wallet. One step gives the coins that are within a year of their seven-year date a new seven-year count, by sending them back to their own address; a single coin is enough, and the wallet says how far off the earliest date is. Like combining, each group is an ordinary transfer. Tested on a chain with a shortened interval: a renewed coin is not swept and the balance is unchanged. Used from a wallet on the development network, with the balance afterwards exactly the height times 50.
- [ ] **RandomX mining algorithm**, tuned for home processors.
  - *Have:* built. The engine is kept inside the repository and reproduces RandomX's official test values; CVN runs it with its own identifying settings, so mining software built for other coins does not produce valid CVN work, while the memory settings that keep graphics cards and custom chips at bay are untouched. The key changes once a day and always sits beyond the reorganisation limit. The algorithm is chosen by block height, so it can be replaced later without restarting the chain; a test chain switches algorithm part-way and carries on.
  - *Also have:* a measurement of what a graphics card gets. The published fast miner cannot mine CVN on a graphics card at all. With a private change to make it work, a current high-end card reached about 770 hashes per second against about 18,000 for a 16-core desktop processor: about 4%.
  - *Missing:* a public testnet; a realistic starting difficulty for launch.
- [ ] **A miner as fast as the best available.**
  - *Have:* a CVN edition of XMRig, the most widely used RandomX miner, published at https://github.com/kalashnikovski/cvn-xmrig with Windows and Linux builds. It differs from XMRig only in CVN's two RandomX settings and in having no built-in donation. A CVN node on a RandomX network runs a work server that such a miner connects to; the node builds and checks every block the miner finds, and pauses its own miner meanwhile. Measured on one 16-core desktop processor with large memory pages on: about 17,900 hashes per second with the CVN edition against about 16,400 for the miner built into the node (the figures in MINING_GUIDE.md). A built-in speed test is included (`--randomx-bench`).
  - *Also have:* the built-in miner now uses large memory pages when the system grants them, which on that processor raised it from about 12,800 hashes per second, without large pages, to about 16,400. Miners who do nothing special still get the ordinary speed; those who enable large pages get most of the way to a tuned miner without installing anything else.
  - *Also have:* the built-in miner no longer slows down on top of a full block. To see whether the newest block had changed it re-read that whole block on every hash, which for a full block took longer than the mining. It now asks for the identifier alone. The fast miner was not affected.
  - *Also have:* the node runs the fast miner by itself. When the CVN edition of XMRig is in a folder named `xmrig-cvn` beside the program, the node starts it, feeds it work, shows its speed on the usual dashboard and stops it on exit; otherwise, or if the fast miner keeps failing, the built-in miner is used. `--miner builtin` chooses the built-in miner, and `--threads N` limits either. An optional processor tuning adds about 7% more with the fast miner. A guide covers the miners, large pages and the tuning: [MINING_GUIDE.md](MINING_GUIDE.md).
  - *Missing:* the fast miner started by the node has not yet been tried on Linux. Antivirus programs may flag a program that starts mining software; this needs checking on testers' machines.
- [ ] **One way to write a block or a transfer.** Built after checking the specification against the code. The block identifier is the hash of the header's fields each written with its length, so two different headers can never share an identifier (an earlier format joined text with dashes, and two different headers could collide there). Every header field has one permitted form. A transfer carries nothing its sender did not sign, and what is signed includes the network's name, so a transfer made for one CVN network is invalid on any other. Reward coins obey the same minimum as every other coin. Blocks are limited to 300,000 bytes, and miners fill them accordingly. There is no uncle share: nodes never verified the named uncle, so it was voluntary in practice.
  - *Decided, 19 November 2026:* the block size stays at 300,000 bytes, after full blocks were seen crossing the development network (Phase 2). There is no uncle share at launch; whether one is ever wanted is to be judged from the share of blocks that lose a race (Phase 2).
  - *Missing:* a public testnet.
- [ ] **How a miner fills a block.** Built: four fifths of a block goes to transfers that pay a fee, highest first; one fifth is kept for fee-less transfers of coins at least a day old, longest-waiting first; space one lane does not use goes to the other. So a fee buys priority, and moving your own coins for free still gets through when blocks are full, while passing coins back and forth to flood the chain does not. This is the published miner's behaviour, not a network rule. Full blocks of fee-paying transfers have been mined on the development network; the fee-less lane has not yet been seen under load there.
- [ ] **Peers that send bad work are cut off.** Built: a peer that sends a block claiming to extend a node's tip with invalid proof of work is disconnected and refused for 10 minutes. Checking a RandomX proof costs real time, so this stops a peer making nodes do it for nothing. Only what is certain counts: a block from another branch is never held against its sender.
- [x] **Addresses that catch typing mistakes.** An address ends with a 4-byte check on the rest, and the rules themselves refuse to make a coin out to anything that is not a well-formed address. Every single-character mistake and every swap of two neighbouring characters is caught. An address saved before the check existed is completed automatically for mining; one typed into a wallet is not. In use by every miner on the development network.
- [ ] **Limit on deep reorganisations.** Built: a node will not replace more than 100 of its own blocks, however much work a competing chain shows. Not yet seen in action on a real network.
- [ ] **Proof that nobody mined early.**
  - *Have:* built. A launch network's first block is tied to a Bitcoin block whose height is announced before that block is mined. Miners supply that block's 80-byte header at the start; the node checks the header carries Bitcoin's proof of work, writes its hash into the first block and dates the first block two hours before its timestamp (Bitcoin lets a block's time run that far ahead, and a first block dated in the future would make honest miners wait). So nobody can mine, or prepare to mine, before the Bitcoin block exists, and nobody can date the first blocks in the past to pull the difficulty down: the difficulty rule counts any date before the Bitcoin block's own time as that time. The software ships with the height fixed and the header open, so its publisher has no head start either.
  - *Also have:* a waiting mode. A node started before the Bitcoin block exists waits and starts by itself when it appears, so everyone who is waiting starts within seconds of each other. It asks five public Bitcoin block explorers and uses a header only when two agree; `--no-anchor-lookup` turns that off for an operator who supplies the header by hand. Rehearsed against a real Bitcoin block on the development network.
  - *Also have:* a rule fixed in advance for the rare case that Bitcoin replaces the anchor block just after it appears and nodes start from two different blocks: the network is the one that begins from the block still in Bitcoin's chain six blocks later. Every node checks this for itself and says so if it is on the wrong side.
  - *Missing:* a real launch. A node cannot yet prove for itself that a header is the block at the announced height: it relies on two of five explorers agreeing, on the earliest date fixed in the release, and on the six-blocks-later check. Following Bitcoin's headers from a block fixed in the release would close that, and is planned before the real network.
  - *Decided, 19 November 2026:* no second source beside the Bitcoin block. One Bitcoin block hash already proves that nobody could know the first block in advance; a second source would add nothing to that and would add a second thing every node must fetch and agree on at the moment of launch.
- [ ] **The CVN Testnet.** Defined (`--network cvn_testnet`), and the network the program runs on when none is named: every launch rule, its own ports, files and message key, the six seed nodes, and a starting difficulty of 2,500,000. Not scheduled: it cannot be started until a Bitcoin height is announced in a release.
- [ ] **Automated tests for every consensus rule.**
  - *Have:* about 210 tests, run on every change and before every release: every file that decides validity has tests, including the reward schedule, the vault, the sweep, the block and transfer format, chain selection, reorganisations, the difficulty rule at its limits and its whole-number arithmetic pinned to exact values. A real chain can be replayed through new code to show that nothing moved, and simulations measure what stop-start mining and chosen block dates earn.
  - *Also have:* tests that start the real program several times over on one machine, each copy at its own address, and take the copies through an ordinary life: seeds, a miner, a second miner arriving late, a transfer handed to a seed, a seed that is killed and comes back, a miner that returns from being cut off, blocks filled to the size limit, and the three ways a newcomer's seeds can be wrong. At the end every node must hold the same block, the same total work, the same vault and the same coins at every address, and coins plus vault must equal what was issued. They found two faults the single-process tests could not (see "Capacity for a large network" and "A miner as fast as the best available"). The network they run on exists only in a program built for testing; no release contains it.
  - *Missing:* the same across separate machines with real distance between them; two halves of a network both mining and then rejoining; the 100-block limit between real nodes. The tests of the difficulty rule mostly check it against its own arithmetic, with the simulations as the only check from outside it.
- [ ] **Public testnet of the launch rules** with outside miners.
- [ ] **Independent review.**
  - *Have:* five rounds of review by several AI models, each testing the others' findings in the earlier rounds, with every finding and what was done about it recorded in the `audit` folder. They found real faults, including one that let any peer replace the first block, and the two difficulty faults above.
  - *Missing:* a review by an independent person or firm.
- [x] **Whitepaper rewritten** to match what is built, and kept in step with each rule change since.
- [x] **Downloads anyone can check.** Each release lists the SHA-256 of every package and of every program inside it, the programs are built so that anyone who builds the same tag gets the same bytes, and GitHub signs each file as built by this project's recipe from this repository at that tag. For release candidate 11 all four programs were rebuilt from the tag on a separate machine and matched.
- [ ] **Launch at a pre-announced time**, from a new genesis block, with every setting published in advance.

## Phase 5: After launch

These were on the roadmap before the launch rules were designed and are still planned. None has been started.

- [ ] **ASIC-neutral proof of work, long term.** RandomX (Phase 3) is the starting point. The mining check is built so that the algorithm can be changed at a chosen block height without restarting the chain, so a later algorithm designed specifically for CVN can replace it if specialised hardware ever appears. Short of a full replacement, CVN's own RandomX settings can themselves be changed and switched on at a chosen height, the way Monero periodically tweaks RandomX to retire any hardware built for the old settings. **We can and will tweak the proof of work if specialised hardware appears**, so the chain stays mineable on ordinary home processors.
- [ ] **Indexed database.** Wallets currently ask a node to scan for their coins; an index would make that fast on a large chain.
- [ ] **Standalone light client (SPV).** A wallet that verifies its own transactions without holding the whole chain.
- [ ] **Scripting engine.** Spending conditions beyond a single signature.
- [ ] **Network alert protocol.** A way to tell every node operator about an urgent upgrade.
